## Problem
U3's deploy tool switches the hooks to a versioned folder and can roll back. When a switch half-fails (exit 4: written, but the check after it failed) or a rollback refuses, it prints a way back: the command to run next. Four KTD 20 review rounds ran on U3 (27, 14, 10 and 10 findings on 11, 10, 7 and 4 lenses). From round 2 on, nearly every confirmed finding sat in that recovery code (the way-back advice, the hand-run fallback, the log's undo stack), not in the deploy or write paths. The worst:
- After a failed undo of version B, the advice named `rollback --to B`, the version the operator was escaping. A test pinned that advice and ran it, asserting "back on B".
- After a write that landed, the advice said "Nothing was written. Put those values back".
- The printed hand-run command was tested only by splitting it with a JS model of POSIX quoting. PowerShell 7, this machine's primary shell, rejects a line that starts with a quoted word (`'node' '...'` is a parse error), so no printed line could run there.

## Root Cause
- Recovery code runs only in an incident, so normal use never exercises it. Its tests are its only runs, and they assert what the author believed the right recovery was. A wrong belief passes green, and the test makes it permanent.
- The advice was a decision tree over states: which kind of log line, where the way back lands, what a re-read shows. Each fix round added states, and the next round found the seams between them. Rounds 3 and 4 trace mostly to the previous round's recovery fixes (insight 002's pattern).
- The quoting model was a map (insight 003): it encoded what POSIX does, and nobody had run the line in the shell it would be pasted into.

## Fix
- **The invariant, written once,** went into every round-4 reviewer's brief:
  - replaying the log names what settings point at;
  - a bare rollback undoes exactly the top switch or refuses by name;
  - no printed advice and no rollback ever points settings at the version being escaped.
- **A rollback line recovers toward where it was going**, never toward where it came from. Advice that cannot be planned falls through to "no way back is known", instead of naming a command that would refuse.
- **Tests run sequences** (deploy, deploy, hand fallback, `--to`, bare rollback) and assert the stack and the settings after each step, not one state's text.
- **The printed line is pasted whole** into a real `sh -c` and `pwsh -Command` in the tests, and `node` is printed bare.
- **Left for later, on purpose:** exit-4 advice that states facts (where settings point, the log's top, that `--to` can point anywhere) instead of guessing the next command. Round 4's last ten findings were all in the guessing.

## Key Insight
A recovery path is the code you will trust most and have run least. Its tests are its only runs, so they pin whatever its author believed: a test can lock in the wrong way back and execute it green. Before you write recovery advice:
1. **State the invariant it must never break** (here: never point back at what is being escaped). Assert it after sequences of operations, not per state.
2. **Prefer advice that reports facts over advice that picks the next command.** Every guessed state is a new seam.
3. **Run every printed command in the shells it will be pasted into.**

## Also Applies To
- Migration rollbacks, undo stacks, restore-from-backup steps, and runbooks generated by code.
- Error messages that tell a person what to do next: they are recovery advice too.
- Any test that pins prose a human will act on: assert the property the prose must hold (its direction, its truth), not only its words.
