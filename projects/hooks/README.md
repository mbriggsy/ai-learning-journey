## Platform Findings

Discovered through empirical testing. Filed as [anthropics/claude-code#42250](https://github.com/anthropics/claude-code/issues/42250).

1. **`additionalContext` reaches the model on PostToolUse and Stop, and a Stop context extends the turn** (probe Q1, CLI 2.1.306 and 2.1.307): both words a probe's hooks handed over were in a request sent to the model (a transcript's `api-request-blob` or `api-request-shape` record), and the model repeated them. The Stop hook then fired again on turn 1's `prompt_id` with `stop_hook_active` true, so its context kept the turn going, like a block does. Q1 measures that firing itself and ties it to the turn by `prompt_id`, because an async Stop hook can set the flag for the whole session: a context delivered without it reads PARTIAL, a measured deviation. VERIFIED also needs the Stop word's first request record to come before turn 2's prompt record, a check the last 2.1.306 run and every 2.1.307 run made and passed: one after it is a measured PARTIAL (the turn extended, but the context reached the model only on turn 2), and one that no turn-2 prompt record places reads INCONCLUSIVE. Every no is guarded. A word the model repeated that no request record holds reads INCONCLUSIVE (the records missed a delivery). An API error ends a turn in StopFailure, not Stop, and leaves no re-firing to see, so a StopFailure, an `is_error` result or a stream that didn't end `done` turns every reading short of VERIFIED into INCONCLUSIVE (a re-firing on turn 1's prompt still VERIFIES). And a CONTRADICTED needs the model to have repeated the session-start word, so a model that repeats nothing never reads as one that got nothing. This retires the 2026-04 finding filed as #42250, that only error-path output (`{"decision":"block"}`, exit 2's stderr) reached the model.
2. **PostToolUse block delivers without undoing the tool result** — useful for reminders after skill completion.
3. **PreToolUse hooks don't fire on user slash commands** — only on Claude's programmatic Skill invocations. PostToolUse and Stop hooks fire in both cases.
4. **A `Skill` hook sees the skill name in `.tool_input.skill`** — exactly the string passed to the Skill tool: a plugin skill as `<plugin>:<skill>` (e.g. `compound-engineering:ce-code-review`), a `~/.claude/skills` or project skill bare (e.g. `ultramode-code-review`). A case-arm name that is not in the installed roster never matches and never says so — `check-config-liveness.mjs` exists to say so.
5. **`onFailure: "block"` makes a guard fail CLOSED** (Claude Code ≥ 2.1.295, set per hook in `settings.json`). Without it, a hook that can't start, times out, or exits with an unexpected code is a non-blocking error and the tool runs anyway. The two PreToolUse guards (`block-webfetch.sh`, `enforce-brief-before-work.sh`) carry it since 2026-10-08 — proven with a missing-script hook in a headless run: with the flag the call was refused (`failed; blocking because onFailure is "block"`), without it the same call ran. It is **ignored on Stop / SubagentStop / TaskCompleted / TeammateIdle** (the binary logs `onFailure: "block" is ignored on Stop`), so `stop-distill-gate.sh` does not carry it; the advisory SessionStart / PostToolUse / Notification hooks don't either — a broken reminder must not block work.
6. **PreToolUse still honors the deprecated top-level `{"decision":"block"}`** (probe Q2, 2.1.306 and 2.1.307), which `block-webfetch.sh` and `enforce-brief-before-work.sh` use; it maps to a deny, and the model reads the reason. When one output carries both forms and they disagree, the deny won both ways on 2.1.306 and 2.1.307. Those mixed arms don't make Q2 VERIFIED, but one whose read ran (the allow won) lowers it to PARTIAL, so a later version's pass rules out an observed flip without proving deny-wins: a mixed arm the model skipped, or whose run failed, leaves VERIFIED standing.

## Tests

```bash
cd projects/hooks && node --test "tests/*.test.mjs"
```

Quote the glob: on Node 24, `node --test tests/` fails with MODULE_NOT_FOUND. CI runs this suite and the squeaky-clean one (`.github/workflows/hooks-tests.yml`) on every change to this folder or to the four skill folders the leak test covers. Each step lists its suite's `tests/*.test.mjs` with bash and fails when none match, because `node --test` reads a glob that matches nothing as 0 tests and exits 0 (a file with no tests still counts as one, so the file count is the guard). The job times out at 15 minutes. The paths filter stays: GitHub skips a filtered run only when a push's diff tops 3,000 files with no match in the first 3,000, CI runs after the push anyway, and the leak stop before a push is U3's pre-push hook, still to be built.

- **`tests/harness.mjs`** runs a hook from an argv array (no shell) with a fixture on stdin, under `tests/hook-runner.mjs` (see Background processes), then reads the result the way Claude Code does: `outcome(event, run)` follows the hooks reference's exit-code, JSON-output and per-event decision rules, and `assertBlocks` / `assertPasses` assert on it. A run whose decision nobody knows is undecided: the harness killed the hook before the CLI's limit (see Timeouts), a background process held its stdout or stderr open (see Background processes), the runner's 1 MB buffer cut it short (see Output past 1 MB), or its JSON breaks a rule no probe has measured (below). Both asserts refuse such a run, even under `onFailure: "block"`, each naming the way out, and its `blocks`, `continues`, `stops` and `failure` throw when read: they are non-enumerable, so JSON, a spread and `deepEqual` leave them out, and a gate test's raw `assert.ok(!o.blocks)` can't pass the run. `assertPasses` also refuses a PreToolUse `ask` or `defer`, since the session decides whether that call goes ahead, not the hook: a `-p` run, where nobody can answer, denies an ask, and a defer ends a `-p` turn with the call unrun, while an interactive session prompts for an ask and ignores a defer with a warning. `assertBlocks` fails both and says why. `decision` is never a pass signal: exit 2, a failure `onFailure: "block"` blocks, and an undecided run all leave it null, so a gate test asserts with `assertPasses` or `assertBlocks`, never on `decision` alone. `harness.test.mjs` plants hooks a careless reading scores wrong (exit 1, JSON after a profile echo, exit 2 with an allow) and proves the assertions catch them. It also checks the output's shape (`validateOutput`: a `hookEventName` that isn't the event or a `permissionDecision` outside its values decides nothing; a PreToolUse `updatedInput` that isn't an object is undecided instead, through `unmeasuredProblems`: the reference gives it no type and no probe has measured what the CLI does with one, so both asserts refuse it, even under `onFailure: "block"`, while exit 2 over it still blocks), drops the fields an event ignores (all of them on StopFailure, SessionEnd, Setup and InstructionsLoaded; `continue` alone on CwdChanged, FileChanged and DirectoryAdded, whose `systemMessage` still counts), scores a Stop hook's context as keeping Claude going, requires a non-empty reason on a Stop or SubagentStop block by decision (the reference calls it required and what the CLI does without one is unmeasured, so `assertBlocks` fails closed), treats exit 2 from a script that doesn't exist as a failure where the reference says so, refuses the events it doesn't model (PermissionRequest, Elicitation and the like) instead of scoring them, and reads only a run shaped as `runHook` returns it. Where the reference and the CLI disagree, the CLI wins and the harness says which probe measured what: Q1 (a Stop context extends the turn), Q2 (a deny, the deprecated block and exit 2 each stop the call; the mixed arms, a deny in one form and an allow in the other, don't make Q2 VERIFIED, but one whose read ran lowers it to PARTIAL, so a later pass rules out an observed flip without proving deny-wins: a mixed arm the model skipped, or whose run failed, leaves VERIFIED standing) and Q11 (the hook env's session id). Every other rule rests on the reference alone.
- **The hook's environment** is this process's minus every `CLAUDE*` variable and the git location variables (lib's `GIT_LOCATION_VARS`: `GIT_DIR`, `GIT_INDEX_FILE` and the rest, matched case-blind), plus 4 of the 11 `CLAUDE*` variables probe Q8 measured on hook envs: `CLAUDECODE`, `CLAUDE_CODE_CHILD_SESSION`, `CLAUDE_CODE_SESSION_ID` (the input's `session_id`, as Q11 measured) and `CLAUDE_PROJECT_DIR`. The rest depend on how the session was launched, so a test of a hook that reads ENTRYPOINT, ATTENDED, PID, EFFORT or ENV_FILE passes them in `env`, which wins over everything. `CLAUDE_PROJECT_DIR` is the `cwd` option, else `input.cwd`: Claude Code keeps it at the launch root while `input.cwd` follows a cd or a worktree, so a test of that case passes the root as `cwd` (or `env.CLAUDE_PROJECT_DIR`) and the subfolder as `input.cwd`.
- **Timeouts.** `runHook`'s 15 s timeout is the harness's, not the CLI's. `outcome()` takes `hookTimeoutS`, the hook entry's own `timeout` in seconds as the entry sets it (fractions allowed), else the event's default: 600 s, or 30 s on UserPromptSubmit and PostModelSwitch; the outcome's `cliTimeoutMs` is that limit in ms. Any other option throws, so a misspelled or ms-sized one can't fall back to the default unseen, and a timeout-named one such as `cliTimeoutMs` gets an error naming `hookTimeoutS`. SessionEnd hooks share a 1.5 s budget that a hook's own timeout raises up to 60 s, and a plugin hook's does not. A run that reaches that limit is a CLI timeout: a failure whose output is dropped, which `onFailure: "block"` turns into a block on an event exit 2 blocks, less the four Finding 5 says ignore it. A hook the harness killed sooner is undecided, and both asserts refuse it. At the harness timeout the hook dies with everything it started (`taskkill /T` on Windows, its own process group on POSIX; a POSIX process that left the group by `setsid` escapes it, as does a Windows one whose parent already exited), and `harness.test.mjs` checks that a child it started is gone after the kill. `elapsedMs` is the hook's own run time, to its exit or to the harness's kill, never to the close of its pipes. The runner re-arms its deadline until the clock reaches it (one `setTimeout` can fire about 2 ms early), so a killed hook's `elapsedMs` is never under the harness timeout; a fake-clock test of `atOrAfter` holds that.
- **Background processes.** `runHook` runs the hook under `tests/hook-runner.mjs`, which times the hook's exit apart from the close of its stdout and stderr: `spawnSync` alone waits for the close, so a background process left on the hook's output would stretch the run and pass its late output off as the hook's. Claude Code finishes reading shortly after the hook's own process exits (hooks reference, "Hooks that start a background process"): a decision printed later is ignored, and an allow followed by an unredirected background process is blocked. So a run whose stdout or stderr stays open more than `PIPE_HELD_MS` (250 ms) past the exit is undecided (`heldOutput`; the run carries `heldMs`), and both asserts refuse it, naming the documented fix: print the decision first, then redirect the background process (`cmd >/dev/null 2>&1 &`). The runner reads on at least twice that margin past an exit that lands just before the harness timeout, so such a run reads held, never closed with its exit; a run built by hand with no `heldMs` reads as closed with its exit. When a run ends with a background job still holding the output, the job dies with the hook's process group on POSIX (a test Windows skips); on Windows it runs to its own end, since nothing built in reaches it once the hook has exited: `taskkill /T` starts from a live parent, and the dead hook's pid can name another process. A runner that gives no result makes `runHook` throw, never a hook that couldn't start, which `onFailure: "block"` would score as a block; `harness.test.mjs` shows it with stand-in runners, one that exits with no JSON and one that hangs past its slack, set through `setRunner` (a setter only that test calls, never the environment). `harness.test.mjs` plants a hook whose background process prints a deny after the hook exits and one that prints an allow and leaves an unredirected job running, each as a node and a bash hook (so the suite needs `bash`, as `block-webfetch.test.mjs` does): both read undecided. A job that holds only stderr open (a node one, and bash's `sleep 0.7 >/dev/null &`) reads held too. A hook that prints and exits, and the documented redirected pattern, read as usual.
- **Output past 1 MB.** The runner keeps at most 1 MB of each stream (spawnSync's `maxBuffer`, which `runHook` used before it). A hook that writes more is killed there, and the run names the stream in `overflowed`, never in `error` (unless the harness's deadline killed it first: bytes still in the pipe after that kill name no stream and kill nothing again, so the run stays a timeout; `bufferStep`): the reference gives the CLI no output size at which a hook fails, so the cut is the harness's, and the run is undecided, refused by both asserts even under `onFailure: "block"`, with the way out (send a `set -x` trace or other bulk output to a file). A buffer kill shortly before the harness timeout stays the buffer's: the deadline leaves that run to the kill already under way, so it is never relabeled a timeout, which at an entry's own limit would read as the CLI's. `harness.test.mjs` plants a flood before an allow, one after it, and one just before the deadline.

## Probes

`probes/` answers the platform questions the flow's design relies on (Q0–Q16 in the our-setup plan) by running throwaway headless Claude Code sessions whose hooks point at `probes/capture.mjs`, then reading what fired.

```bash
cd "$TEMP" && node <repo>/projects/hooks/probes/run.mjs [--only Q1,Q2] [--out <dir>]
node <repo>/projects/hooks/probes/run.mjs --cleanup <run dir>   # delete that run's probe sessions
node <repo>/projects/hooks/probes/report.mjs [--notes <json>] [--doc <file>]   # regenerate the private probes.md (--doc: a file outside every repo)
```

- **One file per probe** in `probes/defs/` (`qNN-<slug>.mjs`), each stating its question and the assumption it tests, with a control arm wherever a broken instrument could read as a "no". A def imports only `../lib.mjs` and `node:` builtins. Every def that runs a session exports its verdict rule as pure functions `run()` returns through (`decide()` in most, beside Q0's `replica()` (and `realSkip()`, which gates its real-tree run), Q1's `delivery()`, Q3's `scratchIsolation()`, Q9's `junctionVerdict()` / `skillCCs()` and Q12's `agentFacts()`; Q13's `callArms()` / `outsideShape()` / `finalVerdict()`, with `nestNote()` only shaping its summary; Q15's `decide()` over `decideC()`, itself over `toolVerdict()`, `bashAttempts()` and `bashResult()`, for its tools part and `decideB()`, over `bPath()` rows, for its omitClaudeMd part), so the rule is tested offline while it stays inside the hashed def file. Verdicts: VERIFIED, CONTRADICTED, PARTIAL (some arms need a human or a later unit; a def flags one whose only open arms are unsettled or blocked, every settled arm agreeing, with `unsettledOnly: true`), INCONCLUSIVE (a control failed), BLOCKED. The runner files anything else as ERROR: a probe that crashes, a def that fails to import, one that returns no verdict or an unknown one, or one that outruns its ceiling (45 min, or the def's own `timeoutMs`). The runner files that one and moves past it once it has ended its own child processes, each with its tree (found by `ParentProcessId` and ended with `taskkill /T /F` on Windows; a `ps` tree sent SIGKILL elsewhere), naming each, and whether it ended, on stderr and in the record's evidence, and exits once the run is filed. A child the Windows listing gave no creation time is named with that reason and left running: its parent id may be one an earlier process held, and `taskkill /T` would take that process's tree. A grandchild whose parent already exited is out of that reach, and the probe's own code may still start more, so the runner still says to wait before `--cleanup`. A def's result can add fields but never replace its id, version, load-bearing flag or hash.
- **Isolation.** A probe session gets this environment minus every `CLAUDE*` variable (a nested session would inherit its parent's session id and messaging socket), the git location variables (`gitEnv()`: `GIT_DIR`, `GIT_INDEX_FILE` and the rest, matched case-blind, so no git call can land on a repo an outer hook names), and `AI_AGENT`, every name shaped like a credential and the gateway pair (lib's `SECRET_ENV`: `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN`, `DATABASE_URL`, any name ending in `_API_KEY`, `_ACCESS_KEY`, `_SECRET_KEY`, `_PRIVATE_KEY`, `_TOKEN`, `_SECRET`, `_PASSWORD`, `_PASS`, `_PWD` or `_CREDENTIALS` or holding `_TOKEN_`, `ANTHROPIC_BASE_URL`, `ANTHROPIC_CUSTOM_HEADERS`, `ANTHROPIC_PROFILE`, `ANTHROPIC_FEDERATION_RULE_ID`, `ANTHROPIC_ORGANIZATION_ID` and `ANTHROPIC_WORKSPACE_ID`, case-blind): a probe signs in with the CLI's own login, straight to Anthropic, never with a key a sourced `.env` left in the shell, through a gateway it named, or as another profile or federated identity (those rank above the login). `ANTHROPIC_BASE_URL` makes a gateway the endpoint, so it receives the login with every request, and `ANTHROPIC_CUSTOM_HEADERS` can carry an `Authorization` header; proxy and CA variables still pass, since a proxy only carries the connection to Anthropic's endpoint. That is a deny list, never an allow list, since the CLI needs `PATH`, its profile folders, `TEMP` and the rest; a def's own variables (Q3's `CLAUDE_CONFIG_DIR`, Q15's `ENABLE_TOOL_SEARCH`) pass as given. It loads no user settings (the live user hooks touch machine-wide `/tmp` markers) and works in a fresh folder under the system temp dir. The one exception is Q3's user-scratch arm, whose user source is a scratch `CLAUDE_CONFIG_DIR`. It launches only after a pre-flight of the same session (same env, sources and workspace) with `disableAllHooks: true` in `--settings`, which outranks user settings, no tools and a debug file. The pre-flight must fire no capture and no hook event, list the scratch skill and none of the live user skills, put `memory_paths.auto` under the scratch folder, and load user skills from it per its debug log; its settings watcher, when that line appears, must list the scratch `settings.json` and never the live one. Otherwise the arm never runs, and its row is isolation-unproven. Every launch carries `--strict-mcp-config`, so no configured, project or user MCP server ever starts. The one MCP server a probe runs is Q15's probe-local stub, a small stdio JSON-RPC script whose source sits in the Q15 def (so the verdict hash covers it), written into Q15's own workspace and passed with `--mcp-config`; Q15's sessions also set `ENABLE_TOOL_SEARCH=false`, so the stub's tool is offered by name, not deferred. Every launch carries a `--settings` file whose `claudeMdExcludes` keeps `~/.claude/CLAUDE.md` and `~/.claude/rules/**` out: the temp dir sits under the home dir, so the pilot's instructions otherwise load as project memory too. The same file sets `crossSessionInbound: "refuse"` unless a def sets that key itself: a `-p` session binds an inbox like an interactive one, so a live session's message could otherwise land in a probe's turn, and a `--settings` value outranks user settings for this key (settings reference; a project or local value can only be stricter). A def that spawns the CLI itself uses `baseArgs()` for the same flags, and a settings file the def wrote is rewritten whenever that merge changes it. A probe that runs a shell command allows exactly that command by a pattern rule (`Bash(node wait.js)` in Q5 and Q14, `Bash(node q8env.js)` in Q8), never a whole shell tool. Q0, the one probe that starts a session in the real tree (`projects/the-back-nine`), passes `--settings` with `disableAllHooks: true` there (flag settings outrank project and local ones; hooks reference, "Disable or remove hooks"), so no hook the real settings chain declares fires. The real run starts only when a replica run under the same flag finished cleanly, fired nothing and listed the same settings files on its watcher line, the replica logs gave a load kind, and the replica alone gave no verdict (`replica()`: a replica whose git top-level isn't its own repo folder, a control hook that never fired, a parent file that loads nowhere, or a deviation in the replica itself), since `decide()` returns that verdict without reading the real tree. Otherwise it is skipped, leaving the real tree unread (PARTIAL, unsettled only, where the replica decided nothing), and the skipped evidence line gives `realSkip()`'s reason, so no session runs in the real tree whose reading can't be used. Each real settings file (`{exists, size, sha256}`) and the names in `the-back-nine/.claude` are taken just before and just after the real run. Any change reads INCONCLUSIVE, ahead of every VERIFIED or CONTRADICTED, and is left as found: restoring it would be a second write to the live tree, over whatever a live session there saved. Q8's interactive arm reads the environment of the session `run.mjs` was launched from, and counts only when that session's CLI is the version under test: `AI_AGENT` and the version in `~/.claude/sessions/<CLAUDE_PID>.json` (read only when that file's pid and session id are that environment's) must name no other version, and at least one must name it. Otherwise the arm is BLOCKED, since a running session keeps its old binary after an update. That launcher reading stands for hook env through Q8's bridge, built from readings only: a PostToolUse whose Bash output carried a `Q8ENV` line with its hook's own session id. A Bash call that printed none is no evidence either way; an arm, or the workflow agent, with no reading leaves the bridge open there (unsettled only), and a reading that disagrees with its hook env is a measured PARTIAL that never says `unsettledOnly`. Q8's claim about workflow agents covers `-p` sessions only, where the main thread and its agents both read `sdk-cli` / `0`; whether an interactive session's agents carry its `cli` / `1` is an open arm, named in every summary and never claimed. Not isolated: each session still writes its project entry to `~/.claude.json`, and Claude Code rotates that file's backups; `--cleanup` leaves the file alone, since live sessions write it too.
- **Results are private.** Captures hold real session ids and paths, so they go to `~/.claude/flow/probes/<cli version>/<UTC stamp>/`, never into this folder. That default may sit in a repo only where git ignores it: both `results.json` and a random extensionless name in the run folder, so a name-only pattern (`results.json`, `*.json`), which hides that one file and leaves the captures beside it committable, reads as visible and the run refuses to start. `--out` refuses any folder inside a git work tree, ignored or not, as `report.mjs` refuses an explicit `--doc` (see The record), and each of these checks fails closed where git can't tell: a folder under a `.git` that git won't open, or one inside a `.git` dir. Each probe writes `<id>/made.json` as it makes folders, so `--cleanup` finds them even after a crash; `results.json` is rewritten after every probe. `--cleanup` deletes only what derives from a `claude-probe-*` workspace in the temp dir that a run listed: the workspace, its transcript folders under `~/.claude/projects` (listed, or found by name: the folder named for the workspace or for a folder inside it, even when no def listed it), and the CLI's task-output folders named the same way under `%TEMP%\claude` (its temp root on Windows; nothing else in that live folder is touched, and on Linux and macOS, where the CLI uses a `claude-<uid>` folder, the default root finds nothing), plus the folders named the same way in the CLI's per-cwd cache, where Q15's stub server leaves its MCP logs (`%LOCALAPPDATA%\claude-cli-nodejs\Cache` on Windows; no default elsewhere). A run during which `claude --version` changed is marked invalid and files nothing.
- **What counts (KTD 10).** `passes.json` files each probe's latest `{verdict, run, hash, at, seen}` per CLI version, the hash covering the def plus `lib.mjs` and `capture.mjs`, and `seen` the measured verdicts filed on that hash. `passedOn(version)` returns a boolean and `passCheck(version)` the detail (`{passed, failing}`); both re-hash those files on disk now: a version passes only when every probe in `LOAD_BEARING` (pinned in `run.mjs`, never read from a def's flag) has a VERIFIED verdict whose hash still matches, and every probe Q0–Q16 has a def. Neither throws: when the check itself can't run (two def files claiming one id, an unreadable passes.json), the version is not passed, with a failing entry whose id is `*`. Editing a def, `lib.mjs` or `capture.mjs` voids the verdicts it backed until they re-run, and two measured verdicts that disagree on one hash fail the probe until its hash (def, `lib.mjs` or `capture.mjs`) changes, so a re-roll never decides it. VERIFIED, CONTRADICTED and PARTIAL count as measured, except a PARTIAL its def flags `unsettledOnly` for a probe pinned in `UNSETTLED_OK` (`run.mjs`: Q0, Q3, Q5 and Q7–Q14, each of which flags its unsettled-only PARTIALs): that one measured as little as an INCONCLUSIVE, so a VERIFIED after it is no conflict. Q1, Q2 and Q15 are never pinned, since their PARTIALs are measured deviations. The gate calls `passedOn` (a boolean); the stored `loadBearingPassed` is only true as of its filing. Re-run the set whenever a session reports a CLI version that isn't in that file.
- **The record.** `report.mjs` rewrites only the block between `<!-- generated:begin -->` and `<!-- generated:end -->` in `~/.claude/docs/plans/our-setup/probes.md`, under the passes.json lock, so evidence recorded by hand outside it survives. It marks a verdict whose `result.json` is missing or disagrees, whose def or instrument changed since, or whose measured runs disagreed. Design notes come from `--notes <json>` (default `~/.claude/flow/probes/notes.json`). An explicit `--doc <file>` must sit outside every git work tree, as `--out` must, or report.mjs exits 1 before writing: the scrubber aliases session ids, API ids and paths, but the workflow and agent ids and transcript keys a finding quotes stay. The default probes.md is never checked: it lives in `~/.claude`'s local-only repo, which tracks `docs/**` on purpose.

## The Hooks

### enforce-brief-before-work.sh

| | |
|---|---|
| **Type** | PreToolUse |
| **Matcher** | Skill |
| **Blocks** | the `ce-work` skill — `compound-engineering:ce-work` (Claude invocations only) |
| **Until** | `/brief` runs |

Gates `ce-work` behind `/brief` so the agent loads documented gotchas from `docs/insights/` before starting work. Uses a marker file (`/tmp/.brief-gate`). Also clears the distill marker when `/distill` runs.

**Workflow and Agent builds are NOT hook-gated — by design.** The gate matches the `Skill` tool only, so a build driven through the Workflow or Agent tools never passes through it. Retargeting the gate onto those tools was considered and rejected (2026-09-30): it would be a new cage on every fan-out, not a brief. The /brief-before-a-unit law for those builds lives in skill and TODO text. The dead `ce:work` and `distill-and-brief:*` aliases were pruned the same day (no such plugin or skill is installed; the liveness check flagged them).

### remind-distill-after-work.sh

| | |
|---|---|
| **Type** | PostToolUse |
| **Matcher** | Skill |
| **Fires after** | `ce-work`, `ce-code-review`, `ultramode-code-review` (bare and `compound-engineering:`-prefixed forms) |

Drops a marker file (`/tmp/.distill-needed`) as a silent side effect. No output — the Stop hook handles delivery at the right moment.

Until 2026-09-30 the review arm matched `ce:review|ce-review|compound-engineering:ce-review` — a skill CE 3.14.3 does not ship (its review skill is `ce-code-review`) — so no review ever set the marker, and nothing said so.

### stop-distill-gate.sh

| | |
|---|---|
| **Type** | Stop |
| **Matcher** | (all) |
| **Blocks** | Claude from stopping if `.distill-needed` exists |

Fires when Claude tries to finish responding. If the distill marker exists (set by PostToolUse after ce-work or a code review), blocks with a reminder to run `/distill`. Clears the marker on block so the agent isn't stuck in a loop.

This is the key timing innovation — Stop hooks fire when work is actually DONE, not when the skill loads.

### block-webfetch.sh

| | |
|---|---|
| **Type** | PreToolUse |
| **Matcher** | WebFetch |
| **Blocks** | `WebFetch` tool |
| **Redirects to** | `mcp__gemini-grounding__search_with_grounding` or `curl --max-time 15` |

Unrelated to the knowledge loop. `WebFetch` has no timeout — agents hang indefinitely. The gemini-grounding server's tools are `search_with_grounding`, `search_documentation`, `search_developer_resources` and `search_reddit`; the redirect named a nonexistent `web_search` until 2026-09-30.

### elite-engineer-session-start.sh

| | |
|---|---|
| **Type** | SessionStart |
| **Matcher** | (all) |
| **Delivers** | The Elite Engineer Protocol manifesto as `additionalContext` on every new Claude Code session, plus a `CONFIG LIVENESS WARNINGS` block only when the liveness check finds something. |

Unrelated to the knowledge loop. Guarantees Claude sees Briggsy's non-negotiable quality bar at the start of every session — no relying on memory being loaded, no relying on "Claude remembers this project." The hook reads the deployed manifesto at `~/.claude/manifesto/elite-engineer.md` and emits a SessionStart JSON envelope with the content.

Paired file — **`elite-engineer.md`** — the manifesto (its source copy lives in this folder; `wc -l` it rather than trusting a line count here — this README said 38 lines long after it had grown to 88). "You are elite. Quality is the deliverable. Here are the non-negotiable rules. Here's the test before every claim." The hook is a thin transport; the manifesto is the payload.

**Rationale:** Captured 2026-04-22 after a sloppy session where Claude called a broken feature "hardened" after writing unit tests around it. Briggsy's direction: *"Figure out a way to NEVER forget that with me. Build software around it, whatever, you can't say you forgot."* Memory files were not enough — SessionStart injection is the mechanism that guarantees delivery.

If `elite-engineer.md` is missing at runtime the hook emits a WARNING payload instead of silently failing — Claude sees the warning on session start and must restore the file before claiming any work is done. (That early-exit branch does not run the liveness check.)

### check-config-liveness.mjs

| | |
|---|---|
| **Type** | Called by `elite-engineer-session-start.sh` — no hook entry of its own |
| **Runs** | Every session start, `/usr/bin/timeout 3 node ~/.claude/hooks/check-config-liveness.mjs` (~0.1 s; a PATH `timeout` is used only if it reports GNU coreutils) |
| **Prints** | NOTHING when all green; otherwise a short `CONFIG LIVENESS WARNINGS` block, appended to the manifesto's `additionalContext` |

Added 2026-09-30 after one research pass found three dead-and-silent wiring defects at once (the `ce:review` arm, the `web_search` redirect, a stale Serena permission). A hook that never matches looks exactly like a hook with nothing to say, so the check looks for the wiring itself:

1. **A skill name in a hook's case-arm that is not installed.** It reads every `case` whose subject variable was assigned from `.tool_input.skill`, in every `.sh` a settings hook command names plus `~/.claude/hooks/*.sh`, and judges **each alternative on its own** — a dead alias beside a live one is still flagged, because a whole dead arm can hide inside a mixed one (the original `ce:work|…|ce:review|…` arm was exactly that). The roster: every **enabled** plugin in `~/.claude/plugins/installed_plugins.json` (`installPath` → `skills/<dir>` and `commands/*.md`, in bare and `<plugin>:<name>` form, plus each `SKILL.md`'s frontmatter `name:`), `~/.claude/skills/*`, `~/.claude/commands/*.md`, and `<dir>/.claude/skills/*` + `<dir>/.claude/commands/*.md` for the project dir and every ancestor.
2. **A settings.json hook (or `statusLine`) command whose script path does not exist** — a token with a script/executable extension and a directory part, after expanding `~`, `$HOME` and `$CLAUDE_PROJECT_DIR`.
3. **A `~/.claude/skills` (or `<project>/.claude/skills`) entry that is a junction/symlink whose target does not resolve.**

**It must never break the manifesto injection.** Each check runs in its own try/catch and an error drops that check's findings (a half-built roster never produces false alarms — an unreadable `installed_plugins.json` skips the skill-name check); the whole script is wrapped and always exits 0; the output is ASCII-only; the session-start hook runs it under `timeout 3`, skips it if `node` or a GNU `timeout` is missing (Windows `system32\timeout.exe` is never used — it rejects the arguments and would silently skip the check), and discards its output on any non-zero exit. Fault-injected 2026-09-30 (syntax error, top-level throw, infinite loop, non-zero exit, `node` absent from PATH): every case still emitted valid JSON carrying the manifesto byte-for-byte.

**Run it by hand:** `node ~/.claude/hooks/check-config-liveness.mjs --debug` (roster size and scanned scripts on stderr). Test-only overrides: `--claude-dir`, `--settings`, `--hook <file>` (repeatable), `--skills-dir`, `--project-dir` — point them at scratch copies, never at a live hook.

**What it does not check:** MCP tool names inside hook text or CLAUDE.md (e.g. the `search_with_grounding` redirect) — enumerating a server's tools means starting the server, which a session-start hook must not do.

## The Full Chain

```
User: "run ce-work on Phase X plan"

1. Claude invokes compound-engineering:ce-work
   → PreToolUse BLOCKS: "run /brief first"

2. Claude invokes /brief
   → PreToolUse: marker created, allowed through
   → /brief loads insights into conversation

3. Claude re-invokes compound-engineering:ce-work
   → PreToolUse: marker consumed, allowed through
   → PostToolUse: drops /tmp/.distill-needed (silent)
   → ce-work loads, agent follows instructions

4. ... work happens ...

5. Claude tries to stop
   → Stop hook: marker exists → BLOCK: "run /distill"

6. Claude invokes /distill
   → PreToolUse: clears marker, allowed through
   → Agent captures insights (or confirms nothing to capture)

7. Claude tries to stop again
   → Stop hook: no marker → allowed through
```

A code review (`compound-engineering:ce-code-review` or `ultramode-code-review`) enters at step 3's PostToolUse: no brief gate, but the distill marker drops the same way.

**Known limit:** both markers are single global files under `/tmp`, shared by every concurrent session and subagent on the machine — a Skill call in one session can set (or consume) a marker another session's hook then reads.

## Deployment

Scripts deployed at `~/.claude/hooks/`. The Elite Engineer manifesto deploys alongside at `~/.claude/manifesto/elite-engineer.md` (sibling directory — content vs code separation). Configuration in `~/.claude/settings.json`:

```json
{
  "hooks": {
    "SessionStart": [
      { "matcher": "", "hooks": [{ "type": "command", "command": "bash ~/.claude/hooks/elite-engineer-session-start.sh" }] }
    ],
    "PreToolUse": [
      { "matcher": "WebFetch", "hooks": [{ "type": "command", "command": "bash ~/.claude/hooks/block-webfetch.sh" }] },
      { "matcher": "Skill", "hooks": [{ "type": "command", "command": "bash ~/.claude/hooks/enforce-brief-before-work.sh" }] }
    ],
    "PostToolUse": [
      { "matcher": "Skill", "hooks": [{ "type": "command", "command": "bash ~/.claude/hooks/remind-distill-after-work.sh" }] }
    ],
    "Stop": [
      { "matcher": "", "hooks": [{ "type": "command", "command": "bash ~/.claude/hooks/stop-distill-gate.sh" }] }
    ]
  }
}
```

This project folder is source control. The deployed copies at `~/.claude/hooks/` (and the manifesto at `~/.claude/manifesto/`) are the live versions.

**Install / re-sync:**

```bash
# Shell hooks + the liveness check the session-start hook calls
cp projects/hooks/*.sh projects/hooks/check-config-liveness.mjs ~/.claude/hooks/
chmod +x ~/.claude/hooks/*.sh

# Elite Engineer manifesto — goes to a sibling dir, NOT ~/.claude/hooks/
mkdir -p ~/.claude/manifesto
cp projects/hooks/elite-engineer.md ~/.claude/manifesto/elite-engineer.md
```

After any source edit in this folder, re-run the copy, then `cmp` each pair — the live and tracked copies must stay byte-identical. The hook reads the manifesto at `~/.claude/manifesto/elite-engineer.md` at session start, so the runtime copy is what Claude sees.
