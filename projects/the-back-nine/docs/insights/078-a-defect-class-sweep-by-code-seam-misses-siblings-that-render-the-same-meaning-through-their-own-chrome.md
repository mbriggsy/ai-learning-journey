## Problem

The U13 doctrine says one screen, one time base: an aged vault re-derives every "years
out" claim to wall time. The hero and floor line were fixed in the U13 review fold. This
session the band's x-axis was caught live saying "Today 58 / 59" on a 2-year-old vault
(the first `?vault=datestale` walk), fixed, and the ultramode review's caller-contract
adversary then found TwoFutures and the C2 SR sentence as un-fixed siblings — both fixed
too. Hours later a 7-reader Caddie panel's False-PASS Hunter found the odds LADDER still
un-re-based: the hero read "6 years out · 9 of 10" while the ladder's own aria read
"Stopping in 8 years … your date" — a blocker-grade contradiction on the magic moment,
after TWO deliberate sibling sweeps of the same class.

## Root Cause

Each sweep enumerated siblings by CODE SEAM: consumers of `dateAnchor`, then consumers of
`formatAxisDollar`/`deriveDecadeAgeTicks` (the shared chrome the band and TwoFutures ride).
The ladder renders offsets through its OWN chrome (`oddsLadderChrome` → `ladderOffsetTick`
/ `ladderMarkAria`) — it shares no import with the fixed surfaces, so no seam-anchored grep
could reach it. The defect class is defined by RENDERED MEANING (every surface that speaks
"years from now" / "today"), and the class's membership is wider than any one code seam's
consumer list. Insight 054's same-words-siblings rule found the copy siblings; this is its
structural cousin — same-MEANING siblings that share no words and no imports.

## Fix

The ladder re-base is filed REQUIRED (TODO item 0) with its design fork named (plan-offsets
0..elapsed are PAST stop-years on an aged vault — drop vs relabel needs a ruling). The
sweep discipline changed: after fixing a meaning-class defect, enumerate every surface that
RENDERS the same meaning — walk the live screen and list each element speaking that
dimension (here: hero, floor line, band axis, TwoFutures endpoints, C2 sentence, ladder
axis + aria, the gate's elapsed line) — then check each against the fix, regardless of
what it imports.

## Key Insight

A defect class named by meaning ("this screen lies about time") cannot be swept by code
seam ("who imports the anchor"). Seam-anchored greps only find siblings that share
plumbing; independent chrome renders the same lie through different code. Enumerate the
class off the RENDERED SURFACE — list every element that speaks the corrupted dimension
(time, money, odds), then verify each one — and treat a walkable live render as the
enumeration source, since the sibling that escapes is precisely the one with no shared
imports to grep. Corollary: making a previously-unreachable surface walkable is itself a
bug-finding act — every rendering of this family was caught within hours of the aged
vault becoming drivable, and never by the 2,159-test suite.

## Also Applies To

- Any future re-based dimension: a currency/nominal-vs-real display change must sweep every
  surface that renders dollars, not just `formatAxisDollar` consumers (the intake echoes,
  the gate read-back, the assumptions panel each own chrome).
- The one-word-per-mechanism vocabulary (line/cliff/step): a rename swept by copy key
  misses a surface composing the word in a slot template.
- The survivor-frame rule (couple vs survivor anchors): any new chart with its own chrome
  re-raises the question independently of `bandAnnotations`.
