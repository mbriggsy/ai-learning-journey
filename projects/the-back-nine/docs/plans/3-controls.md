# Act 3 — Controls

> **Status: SHIPPED — U9–U13 all shipped; Act 3 closed 2026-07-10.** `docs/roadmap.md`'s You-Are-Here table wins on build status and carries the per-unit detail; this line is a pointer, deliberately kept coarse so it does not rot between sessions.

**The goal.** Deliver the "pull it toward you" half of the product as a **shippable cold-read milestone before the solver exists**: the itemized **budget builder** (essentials = the survival floor, discretionary = the surplus), the **two manual controls** (withdrawal **sequencing** + **Roth conversion**, both driving the Act-1 overlays the solver will later search), the **healthcare surfaces** (ACA cliff, IRMAA, HSA) over the Act-1 healthcare overlay, the **sharpen loop** (every assumption visible, and editable wherever the engine takes a value, each edit *sharpening* the answer), and **returning-user re-entry** with honest per-surface staleness. After Act 3 a friend can build a real budget, hand-tune both controls, see the survivor's tax cliff move, and come back tomorrow to a calm, honestly-stale saved answer — all without a recommendation yet.

**Why this is Act 3.** These surfaces all *consume* the first answer (Act 2) and the validated spine + overlays (Act 1) — they make sense only once the confidence statement exists and the engine is deterministic. They are also the entire input + reasoning substrate the Act-4 solver searches: the budget's two-tier essentials/surplus split *is* the lexicographic objective's two tiers; the two manual controls *are* the solver's search axes; the healthcare overlay is the cliff the solver must not silently optimize over. Building and **cold-reading** them by hand first means the solver in Act 4 inherits proven, honest control surfaces instead of inventing them — and the manual milestone is itself a real, usable tool. The honesty bar rises here, not later: every control readout that moves real money must wear its hedge.

**The chain in one line.** `budget → controls → healthcare → sharpen → re-entry`: **U9** compiles an itemized, time-boxed budget into the two-tier (essentials-floor / lifestyle-surplus) reading; **U10** lets the user hand-tune sequencing + the Roth conversion over the Act-1 overlays and **introduces the `require-the-hedge` copyGuard lint**; **U11** surfaces the income-dependent healthcare reality (the ACA cliff, IRMAA, HSA) over the Act-1 overlay; **U12** makes every assumption visible — editable where the engine takes a value, disclosed with provenance where it does not — so each edit *sharpens* the answer; **U13** brings the returning user (and the surviving spouse) back to a re-derived saved answer with honest per-surface staleness.

2. **The single-shared-market-draw / CRN rule is structural and now MORE load-bearing (inherited from Act-1's CRN contract; one-line restatement).** All account buckets — pre-tax / Roth / taxable / **HSA** — share **one** market-return draw per year (the same normals stream as the spine); buckets differ ONLY in tax treatment, never in return assumption. Tax / RMD / conversion / ACA / IRMAA are deterministic post-draw arithmetic consuming **zero** random draws. This lets the two control arms (Unit 10) and the budget's two-track evaluation (Unit 9) read off **identical** futures (signal, not luck), and it **structurally forecloses asset-location**. Per-bucket draws are forbidden. The full contract lives in [docs/architecture.md §3](../architecture.md).

3. **The death-order reading: the probability-weighted MIXTURE, with the conditional filter specified but NOT built (consumes Act-1 longevity).** What ships everywhere in Act 3 is the **default**: the engine's full probability-weighted **mixture** — "whoever outlives the other," the honest number — because death-order turned out to be a per-path sampled outcome with no knob behind it (`longevity.ts:97-135`; Unit 10 shipped without one and Unit 12 confirmed it is not an engine parameter). The contract is kept because the *shape* of any future conditional view is decided and the substrate for it exists: `sampleCouplePath` retains `firstToDieIndex` per path, so "if one of you outlives the other" would be **a CONDITIONAL view that FILTERS the existing path population — never a re-draw, never a re-index of which spouse is the survivor** — conditioning on the sub-population where the chosen spouse dies first, same seed, same draws, CRN-safe by construction. It would be labelled a hypothetical, **never a prediction** (R12), never a deterministic to-age horizon, and it would carry a **thin-subpopulation guard**: below a minimum path count it widens its hedge and declines a precise frequency rather than show a noisy number. Survivor-spending ratio and per-person retirement years ARE single model fields — an edit from either surface recomputes **both** the spine and any open control under the unchanged seed. The survivor's **MFJ→single threshold flip for BOTH IRMAA and the ACA-FPL basis** is real today and rides the per-path sampled first death directly, not a user-chosen order.

## Unit 9 — Budget builder (itemized, time-boxed, two-tier)

*Essentials = floor / discretionary = surplus; the two-tier lexicographic headline reading.*

> **The two-date split rides this unit — no new budget mechanism.** The fuck-off date's **floor vs lifestyle dates** (R27) are this unit's two-track compilation consumed by the date-search (C3, shipped in Act 1): the two dates **coincide** in the degenerate single-total-spend case via this unit's existing **degenerate-collapse**, and separate when the budget splits the tracks — C3 consumes whatever two tracks `budgetToSpending` emits; nothing in the date-search is rebuilt. The mixed date outcomes — `{floor: date, lifestyle: no-date}` and the `floor > lifestyle` 100%-FPL-floor signature — were dark before this unit; the result *shape* already admitted them from C3, and the behavioral tests ride here. **The medical double-count was closed by making one source authoritative.** The HSA qualified-spend cap rests on the cap-only containment premise (the household spend figure already *includes* out-of-pocket medical), so an itemized medical line that ALSO fed `oopMedical[t]` would double-count medical, and one that silently replaced it would zero the HSA cap. The budget therefore carries **no user-entered medical line at all**: `compileBudget` injects the intake's own `health.oopMedicalAnnual` scalar — the SAME field the overlay's `oopMedical[t]` stream is filled from — as a sticky, lifelong, essentials-tier amount, with a per-year fail-loud containment gate as the belt to that braces. The R27 `floor > lifestyle` inversion stays unreachable in v1 (proportional-drawdown MAGI coupling); its render arm is fixture-pinned and reactivates with Unit 10's conversions.

**Goal.** Let the user build their real spending as an itemized, categorized, **time-boxed** budget whose structure *is* the lexicographic floor/surplus split — and read the answer as a **two-tier verdict** (essentials safe in X of 10; full lifestyle holds in Y of 10) over the *same* outcome-state set, never a new state.

**Requirements.** R20 (itemized, categorized, time-boxed; essentials = floor, discretionary = surplus); R2 (survival-vs-lifestyle separation, Kitces "trim, not go hungry," no color-alone); R19 (budget sanity); R8 (the budget is the *deepening* of the single-total-spend answer, reached via the sharpen loop, never the on-ramp). The requirement text is in [docs/product.md §7](../product.md).

**Dependencies.** Act-1 U1 (the spine — evaluates both tracks on one draw set), Act-1 U2/U3 (overlays — the pre-65 gap cost is income-dependent, computed by U3, never user-typed), Act-2 U5 (the `memoryModel` orchestrator — a budget edit recomputes through it; R19 grammar), Act-2 U6 (viz tokens for the two-tier readout), Act-2 U7 (outcome-state set + copyGuard catalog).

**What it delivers.**
- **Line-item shape (decided):** `{ category, label, annualAmountReal, tier: 'essentials' | 'discretionary', startYear, endYear? }` — the window shipped as **two flat integer fields, not a nested object**, and an **ABSENT** `endYear` means lifelong. A `null` there is forbidden outright (the `IncomeStream.endAge` absence precedent; DND 009 — a null in a number slot is named corruption, and `JSON.stringify`/IndexedDB silently null a sentinel). **Time-boxed** is first-class: a travel item runs years 1–N then stops. Forward-looking **planning** input, not back-looking expense tracking (the tracker lane is explicitly out — see the scope boundaries in [docs/product.md §7](../product.md)). `startYear`/`endYear` are integer **offsets from the HOUSEHOLD work-stop anchor** — year 0 is the year work stops, which for an already-retired household is now and on the date route is the swept candidate offset, so the window is calendar-planned and per-candidate expansion stays deterministic and CRN-safe; a window clamps to `[0, horizon]` and truncates at a per-path death per the survivor-spending composition rule below. **All `annualAmountReal`s are today's-dollar (real) figures — the field name carries the convention** — `budgetToSpending` emits real per-year vectors and the engine applies the methodology inflation default, matching the spine's inflation-adjusted convention so reduce-to-spine holds for itemized budgets too.
- **Healthcare is NOT a budget category — the conclusion the seam to Unit 11 actually reached.** The shipped category set is `housing · utilities · food · transportation · travel · gifts · other`, with no health or medical member, because **any user-typed health amount is wrong in one of two directions**: a flat pre-65 gap figure silently misses the conversion↔subsidy interaction, and a typed medical line either double-counts the out-of-pocket medical the HSA cap is sized off or silently starves that cap. Both dollars come from the engine instead. The **pre-65 gap cost** (ACA premium − PTC, MAGI-dependent) is computed by the Act-1 U3 overlay and surfaced through Unit 11; it belongs to the survival floor — you cannot go uninsured pre-65 — and because the dollar is MAGI-dependent while the two tracks spend differently, **it resolves to a *per-track* value**: the essentials-only track's lower spend yields lower MAGI, more PTC, and a **lower net premium** than the full track, U3 computing it inside *each track's own* MAGI fixed point. The **out-of-pocket medical** figure is injected from the intake scalar as described above. A scoped out-of-pocket-only category could join additively later.
- **Two-track compilation (the structural realization of the two-tier reading):** `budgetToSpending` emits **two** per-year spending vectors from one budget — an **essentials-only** track (Tier-1 floor) and a **full** track (essentials + discretionary). The engine evaluates **both thresholds against the SAME path population on the SAME single shared draw set** (contract #2): "essentials covered every year" (Tier-1) and "full lifestyle covered every year" (Tier-2). ONE shared draw set but **two decumulation + overlay passes** — essentials-only and full are distinct portfolio trajectories, never the full-spend run read twice. This is the engine half of R21's lexicographic structure the Act-4 solver later optimizes (objective ≡ headline metric); Unit 9 builds the *reading*, Act 4 builds the *objective over it*.
- **Two-tier headline reading (NOT a 7th state):** the headline composes **two** outcome-state-tagged readings over the *same* engine-owned six-state enum (Act-2 U7) — an essentials-floor verdict + a lifestyle-surplus verdict ("your essentials are safe in 10 of 10 futures; your full lifestyle holds in 7"). The negative-tier copy is **action-first / Kitces** ("in the other 3 you'd trim discretionary, not go hungry"), and the non-color signal grammar carries each tier's state independently. State-*selection* stays engine-owned in `confidence.ts`; `TwoTierHeadline.tsx` is a pure presentation composition of two already-tagged states. **Degenerate collapse:** when the full track is byte-identical to the essentials track (no discretionary present), `TwoTierHeadline` renders the **single-metric** statement verbatim, not two identical tier verdicts — this is precisely what keeps the reduce-to-spine headline byte-identical.
- **Spending shape is user-set, never solver-recommended:** a go-go-years front-load is a user-set per-year multiplier on the **discretionary** track only (the solver optimizes *funding*, not how you live). U9 owns the shape control and surfaces its honest consequence on the surplus tier; it never proposes a shape.
- **Reduce-to-spine invariant (the budget's golden anchor):** a budget that is a **single lifelong essentials line equal to the first-answer total-spend figure** must compile to the *exact* single per-year spending vector the first answer fed the engine → the **saved seed/headline is byte-identical** to the single-total-spend answer. The single-total-spend answer is the **degenerate budget**; itemization is the deepening, never the on-ramp (R5/R8). Migrating single-total → itemized preserves the seed.
- **Survivor-spending composition (the seam to the survivor floor — R17, the product's emotional core).** The survivor-spending ratio (the Act-1 U1 default) is applied **per-path at the sampled first death** to the compiled tracks: it scales the **discretionary** track and the **discretionary portion of essentials only** — **sticky survival essentials do NOT scale by the couple ratio**, so the Tier-1 survivor floor is never silently understated. **Sticky is the shipped predicate `essentials-tier AND a category whose cost does not shrink when one person is gone`** — `housing`, `utilities`, and `other`, plus the injected out-of-pocket medical; `food` and `transportation` scale. A fresh line defaults to `other` + essentials, the neutral unclassified pick, which deliberately **errs sticky** at widowhood (insight 055's conservative direction — an unclassifiable survival cost must never scale down silently). **Degenerate-inert:** in the degenerate single-essentials-line budget the composition is inert (the ratio falls back to flat-on-total) so the survivor-year vectors stay byte-identical. The composition lives in `budgetToSpending`, not `simulate`, and the ratio itself is one of the two genuinely editable methodology knobs (Unit 12).
- **R19 (contract #7):** non-negative `annualAmountReal`; `endYear ≥ startYear` when present; a zero-essentials "everything discretionary" budget is **coherent** (Tier-1 floor trivially safe) but **warned** calmly. Reuse Act-2 U5's R19 grammar.

**Test scenarios.**
- Happy path: a multi-line budget (lifelong essentials + a 20-yr travel discretionary item) compiles to two per-year vectors; the headline reads two tier-verdicts; the discretionary track drops out after year 20 (time-box honored).
- Edge (reduce-to-spine): a single lifelong essentials line = the first-answer total → the compiled vector is **byte-identical** to the single-total-spend answer under the same seed, the survivor-spending composition is **inert** (flat-on-total), and the rendered headline is the **single-metric** form, not a doubled tier pair (the budget's golden anchor).
- Edge (tier-ordering monotonicity — golden invariant): for any budget, Tier-1 (essentials) `X-of-10` ≥ Tier-2 (full) `X-of-10`, asserted **path-for-path** on the shared draw set (every full-success path is an essentials-success path). - **Per-surface multi-clock staleness (contract #6 — a clock exists iff the engine consumes a year-stamped parameter, and gates only its surface):**
  - **wall-time since last edit** + the **app methodology-default vintage** (new conservative-return/longevity defaults shipped since save AND never user-overridden → a calm "we've updated our default assumptions" note; user-overridden assumptions are immune) → gate the **spine verdict**.
  - **tax-table vintage** (the bracket/standard-deduction fixture, carrying its **OBBBA-2025 legal-basis as provenance** so a statutory change reads as a vintage bump, not inflation drift) → gates the **controls/lever only** (the spine is tax-blind). It is **exposure-gated on `overlayBuilt`**: a save-ready household with $0 accounts and Social-Security-only income takes `buildOverlay`'s degenerate early return, never reads the tax family, and recomputes byte-identically under any vintage — firing there would alarm them about a rulebook they never read. The **per-state** profile clock rides alongside it, gated on the state the run actually priced and compared per state, so an NC rate step never alarms a PA or FL vault (a Florida vault, a constitutional $0, can never fire). The plan's "show the vintage at the control when it is opened" was **not** what shipped, and could not be: nothing is held back under a saved vintage for a caveat to qualify. The fired clock speaks **once, at the re-entry gate**, in its own named line (`reentryChrome.ts:89` pushes `stalenessTax`, "Tax rules have been updated since your save — this reading uses today's"), and the hero carries the standing companion "Figured under today's rules, from the numbers you saved."
  - **Healthcare vintages (net-new) → gate the healthcare surfaces:** the **ACA legislative status** (the load-bearing clock — cliff-on vs enhanced; the re-verify-at-build status), the **applicable-% table**, the **IRMAA brackets**, the **Part B premium**. A saved healthcare cost is flagged stale when any has moved; the ACA-status clock is the most consequential (it can flip the whole pre-65 calculus). The status note is dated and honest.
  - The **undetectable balance-drift clock** (real portfolio drifted; no aggregation): a calm **"is this still your balance?"** confirm before presenting the saved verdict as current. **For an accounts vault it confirms the per-bucket split** (pre-tax / Roth / taxable / **HSA**), not just the total — the pre-tax pool's drift relative to Roth changes the control calculus more than the total does; "something changed" routes into the **guided walk-through** — accounts are edited where they were entered, the Unit-12 panel precedent — with the hydrated draft already installed so every other answer is preserved, and the terminal advance recomputes as always. SS staleness is folded in as "are these still your benefit amounts?" (SS benefits are user-entered, not a year-stamped fixture — no separate clock).
  - **Budget time-boxed clocks (net-new) → gate the budget surface:** a budget line whose **window has advanced** since save (a travel item now past its `endYear`) gets a calm **re-confirm** ("your travel budget was set to end last year — is that still right?") rather than silently spending past its window. It applies to **already-retired (spine-route) households only**: their year-0 anchor is the save's `startCalendarYear`, whereas a date-route household's budget anchors to the future crowned work-stop year, so no window can be "past" before work actually stops.
- **The date answer joins the per-surface staleness/re-entry machinery (the most time-denominated answer in the product would otherwise have no clock):**
  1. **Fixture-vintage clocks (per contract #6), gating the DATE surface:** the **contribution-limit table vintage** (answer-relevant, not intake-only: the per-runway-year catch-up step-down shapes the projected stream, so a vintage move shifts the date) and the **ticker-blend / TDF static-snapshot vintage** (a stale snapshot silently misstates the household stock weight).
  2. **User-entered re-confirms ride the existing balance-drift confirm class, NEVER vintage clocks** (the SS precedent above): account values / contributions / salary join the "is this still your balance?" confirm; the entered **ACA quote** gets an **"is this still your marketplace quote?" plan-year re-confirm** (marketplace premiums reprice annually — user-entered, so a confirm, not a fixture clock).
  3. **The date re-presentation rule:** re-presentation renders the **wall-time-stable calendar label** (`startCalendarYear + Y` — arithmetic over persisted fields, so it reads the same on any later day and under any fixture vintage) and **RE-DERIVES the relative "~N years out" framing from current wall-time** — never a replayed relative string (the date answer decays with pure time passage — ages advance against the saved t=0 anchor — so a sufficiently old save routes to **recompute** via this unit's existing re-run rule, never re-presents as current). Act-4 U17's stale-recommendation rule is **untouched** by this (the date is an answer, not an executed action, so it never faces U17's admission test).
- **Absent-stamp default:** a spine-only vault (saved before the stamps existed, or by a user who never opened a control) has no tax/health stamp → `staleness.ts` treats an **absent** stamp as **"not applicable"** (no false stale), never "infinitely stale." Stamps live on the model so staleness is computable offline.

**Test scenarios.**
- Happy: unlock → saved verdict **re-derived** under the saved seed (byte-identical), shown immediately (no intake re-run); the sticky baseline is re-seated from it.
- Integration (the survivor door): forgotten passphrase + intact vault → **in-place recovery-passphrase unlock** (shipped in U8; asserted here end-to-end with re-entry) → set new daily passphrase (mandatory blocking gate, `passphraseWrap` re-minted) → current model recovered.
- Error paths (consume Act-1 U4): wrong passphrase → calm retry, no lockout, no leak; data-damaged → "use your export"; no-vault/post-eviction → restore is a first-class entry.
- Edge (tax staleness, control-scoped): tax-table vintage older than current → a calm note on the **control**, **not** on the tax-blind spine verdict; a household whose run never built the overlay stays silent, and a state's profile move fires only for a vault that priced that state.
- Edge (healthcare staleness): a saved ACA cost is flagged stale when the legislative status / applicable-% / IRMAA brackets / Part B premium has moved; the ACA-status note is dated; the gate is on the healthcare surface only. A **re-verify that confirms the same law does NOT fire** — `acaVerifiedOn` is excluded from the moved-compare, or every vault would go stale monthly on provenance alone.
- Edge (budget time-box): on a spine-route vault, a travel line past its `endYear` triggers a calm re-confirm, not silent over-window spending; a date-route vault's windows cannot expire.
- Edge (fired clock vs quiet clock): with a clock lit, the surface shows the current-vintage recompute plus the calm "assumptions updated" note, never the saved figure; with no clock lit, the persisted-seed recompute is byte-identical to the saved answer and no note appears.
- Edge (accounts balance-confirm): re-entry on an accounts vault gates a **per-bucket** (incl. HSA) "is this still your split?" confirm before the verdict renders; taking the update affordance routes into the guided walk-through with the draft preserved. On a read-only second tab the read-back still shows and the update affordance is withheld — a dead-end CTA is the lying-remedy shape.
- Edge (date staleness): a contribution-limit-table or ticker-blend-snapshot vintage move flags the **date** surface stale; account values / the ACA quote ride the balance-drift confirm class, not a vintage clock; a sufficiently old save routes the date to recompute, never re-presents as current.
- Edge (absent stamp): `staleness.ts` on a spine-only model treats every absent stamp as not-applicable (no false stale).
- Edge (app-default vintage): a new default σ shipped since save, never overridden → a calm "we've updated our default assumptions" note on the spine; a user who overrode is immune.

**Verification.** A returning user sees their saved answer re-derived behind an unlock — byte-identical when nothing has drifted, and the current-vintage recompute with a calm note when something has — with honest per-surface staleness across the tax, healthcare, budget, and date clocks, is nudged to confirm the balance (per-bucket, incl. HSA, for an accounts vault) before trusting a stale verdict, and — critically — **the surviving spouse has a specified door back in** (in-place recovery with a mandatory new-passphrase gate). **Passing the N=1 cold-read on the re-entry staleness + balance-confirm + survivor-recovery copy (honest, not alarming) is an Act-3 exit condition.**

**Feeds forward to Act 4.** The per-surface staleness map built here is the groundwork Act-4 U17 inherits and **tightens** for a saved recommendation. The drafted "inversion" is refuted (`4-recommendation.md` ruling 6): the spine never re-presented under a saved vintage either, so U17 adds a stricter admission test — the fingerprint, the solver code version and the record's own era must all hold — rather than an opposite rule. A saved control what-if carries no record and rides these clocks; a saved executed action must additionally survive that test, and reads "the action we recommended may no longer be advised" when it does not. See [docs/plans/4-recommendation.md](4-recommendation.md), Unit 17 + contract #8b.
