# U17 S5 — execution plan (the build order)

> **What this is.** The ordered, buildable steps for S5, derived 2026-07-26 from a six-seam read-only
> scout, then rebuilt twice against adversarial review — v1 drew 5 P0 / 5 P1 / 9 P2 across three lenses;
> v2 drew 2 P0 / 8 P1 / 9 P2 across four, **all four returning `holds=false`**. Every surviving P0 and P1
> is folded in below.
>
> **Precedence.** [`act4-u17-saved-recommendation-build-spec.md`](act4-u17-saved-recommendation-build-spec.md) §S5
> stays canonical on the *shape* and on the amendments. This file is the *order*; it never overrides the spec.

## The three rulings this plan is built to (Briggsy, 2026-07-26)

1. **The no-vault tap routes into the ceremony.** The gesture mints onto the draft and opens firstSave,
   mirroring `deriveResultSave`'s `unsaved → {kind:'first'}`. The control is never dead on the
   no-vault path — that path is every dev seed, the Caddie walk and the fit gate. **The CTA names the
   escalation BEFORE the tap.**
2. **The CTA tells the whole-plan truth up front.** `session.save()` writes the ENTIRE scenario
   (`session.ts:600`), so the tap also commits unsaved edits. The control says so before the tap — not the
   confirmation after. A CTA implying a note-only write is calm-but-wrong.
3. **The record card is MINIMAL** — that a saved read exists, its age, whether it still holds, and the
   re-open CTA naming its cost. It does **not** quote the remembered grade/verdict enums. Those stay
   persisted, so the card can grow later with no schema change.
